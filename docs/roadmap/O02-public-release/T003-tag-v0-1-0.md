## Contexto

picokit tiene CI con `go-release.yml` de crossbeam que publica automáticamente al detectar un tag semántico `vX.Y.Z` en un push. El proceso es:
1. Asegurar que todos los cambios de T001 y T002 estén commiteados y pusheados.
2. Crear el tag `v0.1.0` y pushearlo al remote.
3. El workflow `release` en CI se encarga de publicar el release en GitHub.

No requiere crear un release manualmente en GitHub; el workflow lo hace.

## Alcance

3. Pushear el tag al remote (`git push origin v0.1.0`).
4. Verificar que el workflow `release` se dispara y completa.

**Out**:

- No crear ramas adicionales.
